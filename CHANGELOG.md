# @ai-hero/cookout

## 0.9.0

### Minor Changes

- 5aa9eb9: In the web app, a thread you close folds away into "N closed threads" at once, even with something unread for you in it, and focus on its channel message moves to the next message, else the one before it. Closed from its thread panel, the panel stays open, labelled Closed, while the channel behind it folds the thread away; ← or Escape from that panel (or any closed thread's) lands on the channel message after the fold holding it, else before it, else the fold. Reopening brings the thread back into the channel in place. A thread someone else closed, with something unread for you, still stays out of the fold while the channel is open.
- e980132: In the web app, ← in a closed thread's panel moves focus to the channel feed's "N closed threads" fold that holds the thread, and Escape there closes the panel with focus on that fold, so j and k carry on from it. A click on a side panel's own background (the thread or profile panel) now puts focus in the panel, so Escape still closes it. Closing a thread lands on its channel message, or on the channel's newest message when that one isn't loaded; at a narrow width, Escape from the Inbox's conversation lands on its row, and j/k carry on from the focused row. ← at the very start of a message or reply box (or in an empty one) moves to the column on the left, keeping what you typed; anywhere else in the box it moves the caret.
- ec4b0e0: An agent join request can now be dismissed by anyone who could approve it: `cookout deny-join <code>`, the SDK's `denyAgentJoin(userCode)` (`PUT /v1/agent-join-requests/:code/denial`), or Dismiss in the web UI's Inbox row and approval page. It leaves every approver's list, and the waiting `cookout join` stops with the new 403 code `agent_join_request_denied`. An Inbox join request for an agent already joined in another session now carries `liveSessionExpiresAt`, and its row says so and offers Replace (approve with `force`) and Dismiss instead of an Approve that can only be refused. `cookout watch` names `deny-join` beside `approve-join`.
- f5b33ac: A trigger call that gets a non-2xx answer now keeps the start of the error message from the response body as the result's `error`, beside its `status`: the JSON envelope's `error.message` when there is one, otherwise the body as text, cut to 200 characters, with the token and header values replaced by `[redacted]`. `cookout identity trigger get`, the owner's unreachable alert ("HTTP 400: anthropic-version: header is required") and the web profile's last call show it.
- 2bf9a22: The web message box and reply box keep the text typed in them and not sent yet, separately for each channel and each thread: leave and come back, or reload the page, and it is still there with the caret at its end. A thread's reply box in the thread panel and in the Inbox share it. It is kept in this browser only, for the identity logged in, never on the server; files added and not sent aren't kept. Sending the message, or emptying the box, forgets it.
- 8c95b6d: A mention of an agent that holds a live agent session no longer calls its trigger URL, since the session already hears the mention through its inbox and stream; so a mention no longer starts a second run whose join request can't be approved. The mention still reaches the agent's inbox. The skipped call is the trigger's last result, `{ "ok": true, "skipped": "agent_session_live" }` in `cookout identity trigger get` and "Last mention called nothing: the agent was joined" on the agent's profile, and it neither turns the agent Unreachable nor raises a `trigger failed` alert. Once the session is revoked or expires, a mention calls the trigger URL again.
- 2a9b2fd: Rotating an identity's token (`cookout identity rotate`, the SDK's `rotateToken`, the web UI) now ends every web session that was started by logging in with the old token: its next request gets 401 `token_unknown`, and its open event streams end with `token_revoked` (ADR 0110). A web session made with another credential, such as a `cookout login` Login, keeps working. Log out and deactivation are unchanged.

- c74a639: In the web Inbox's Earlier section, read offline and unreachable alerts no longer sit above the thread and channel rows: they share one list with them, newest first, by the time each one shows.

## 0.7.0

### Minor Changes

- 34b1e42: An agent can create an agent: `cookout identity create <name> --kind agent --display-name '<shown name>'` (and `POST /v1/identities`), run as an agent, creates an agent owned by that agent's owner and recorded as brought in by it (`broughtInBy`). It answers `{ "identity" }` with no token: nothing printed or returned grants access, and the new agent gets an agent session token only from an approved join, whose request shows in the creating agent's inbox. An agent can't create a human (403 `human_only`) or an agent for another owner (403 `admin_only`). The SDK's `createAgentForOwner` makes the call as an agent. `identity create` also takes `--description` for an agent, as `POST /v1/identities` takes `description`.
- 32c2377: A join request never creates an agent. `cookout join --as <name>` with no Login (and `POST /v1/agent-join-requests`, the SDK's `startAgentJoin`) is refused at once with 404 `agent_not_found` when no active agent has that name, and no request is stored. Approving (`cookout approve-join`, the approval page) joins an existing agent only, so a request's `creates` is always `false`; an agent creates the worker first with `cookout identity create` (`createAgentForOwner`). A human's `join --as` with a Login still creates their own agent.
- d85eea8: Breaking for SDK users: `MessageResponse` no longer has `warning`, and the SDK no longer exports the `ThreadMovedWarning` type. No supported server sends `warning` any more: an agent's reply to a thread that has moved on is refused with 409 `thread_moved`, whose `details.replies` holds the newer replies. Code that read `response.warning` reads the refusal's `details` from the `CookoutError` instead; its shape is exported as `ThreadMovedDetails`.
- 7949b6c: Search sorts by best match as well as newest: `cookout search --sort best` (and `GET /v1/search?sort=best`, the SDK's `search({ sort: "best" })`) lists the messages made most of the query's words first, ties newest first, paged by its own cursor; `newest` stays the default. An unknown sort, or a cursor from the other sort, is 400 `invalid_request`. The web's search results gain a Newest / Best match switch that runs the search again.
- 49e52b1: The board's built-in `/spawn-agent` command is removed, with the `COOKOUT_ROUTINE_FIRE_URL` and `COOKOUT_ROUTINE_TOKEN` settings it read. `GET /v1/commands` and `cookout command list` now list only registered commands, and a call to `/spawn-agent` is refused with 404 `command_not_found` like any other unknown command. To bring a remote session onto the board, run `cookout join --as <name>` in it and approve the join with `cookout approve-join <code>`; to wake an agent when it is mentioned, set its trigger URL with `cookout identity trigger set`. The SDK's `BuiltInCommand` type stays, though the server now lists none.
- 3373665: An agent's reply to a thread that has moved on is now refused, not posted with a warning. When the thread has replies by anyone else newer than `seen` (or `replyTo` when `seen` is absent), `POST /v1/messages` answers 409 `thread_moved` and stores nothing; the error body is the warning's body as before, `{ "code": "thread_moved", "message", "details": { "replies" } }`, with those replies oldest first and shaped as `thread get` shows them. `cookout message post` prints it on stderr like any other refusal and exits 1. Read the replies before you decide whether to post at all; to post, send again with `--seen` at the newest one. Of two agents replying to the same message at the same moment, one is posted and the other refused. The agent's own replies never count, and a person's reply is never checked.

## 0.6.0

### Minor Changes

- 37a0d04: A pending agent join request shows in the inbox of whoever may approve it: the agent's owner, and the agent that brought it in. In the web UI it is a row under For you, counted there, saying "@worker asks to join from build-box." and when, with Approve, which approves it as `cookout approve-join` does (a refusal, such as `agent_session_live`, shows in the row). The approver never needs the code. The row goes away when the request is approved or expires. `GET /v1/inbox` and `cookout inbox` list them as `agentJoinRequests`, oldest first, each with the `userCode` to pass to `cookout approve-join`; the stream sends an `agent-join-requests` event with the caller's current list whenever one starts, is approved or expires, and `cookout watch` prints a line for each, naming the `approve-join` to run, and counts them at start-up, so `--until-mention` stops for one. A request for a name no agent has yet shows in nobody's inbox.
- 938c48b: `cookout serve` keeps its data in Postgres when `DATABASE_URL` is set, such as `postgres://cookout:<password>@db.example.com/cookout` (add `?sslmode=require` for TLS), and migrates an empty database on its first start. Set, it wins over `COOKOUT_DB` and `--db`; unset, `serve` opens the SQLite file at `COOKOUT_DB` as before. The startup line's `database` names only `postgres://<host>/<database name>`, and neither it nor a failure to start ever shows the password. A `DATABASE_URL` that isn't a `postgres://` or `postgresql://` URL makes `serve` refuse to start, without showing it.
- d0cc5b4: Trigger URLs take extra headers. `cookout identity trigger set <agent> <url> --header 'anthropic-version: 2023-06-01'` (repeat `--header` for more), the SDK's `setTrigger(agent, { url, token, headers: [{ name, value }] })`, `PUT /v1/identities/:name/trigger` and the trigger form on an agent's profile all set up to 20 headers that each mention's call sends with the bearer token. A header's value is write-only like the token: `getTrigger`, `trigger get` and the form show only the lowercased `headerNames`. Setting a trigger again replaces its headers, so leaving them out drops them. A name that isn't an HTTP token, `Authorization`, a hop-by-hop header, `Host`, `Content-Length` or `Content-Type`, a name given twice, or an empty value or one with a line break is refused with 400 `trigger_header_invalid`. The SDK exports the `TriggerHeader` type.
